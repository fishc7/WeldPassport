# WeldPassport — Project Rules

## 1. Основной принцип

Главный принцип:

Сначала архитектура, потом код.

Рабочий цикл:

Архитектура
→ Решение
→ Prompt для Cursor/Claude Code
→ Реализация
→ Diff
→ Приёмка

---

## 2. Архитектурные правила

1. ADR являются источником истины для архитектурных решений.
2. Новая функциональность сначала проходит архитектурную сессию.
3. Нельзя менять архитектуру без согласованного решения.
4. Существующие проектные паттерны имеют приоритет над новыми предложениями.

---

## 3. Правила разработки

Каждая задача должна иметь:

- цель;
- границы изменений;
- критерии приёмки.

Один Task = одна зона ответственности.

Этапы разработки принимаются отдельно:

Domain Model
→ Migration
→ Workflow
→ Service
→ API
→ Tests

---

## 4. Работа с Cursor / Claude Code

Перед реализацией обязательно создаётся Prompt.

Prompt должен содержать:

- контекст;
- цель;
- разрешённые изменения;
- запрещённые изменения;
- критерии готовности.

AI-агент не должен:

- менять архитектуру самостоятельно;
- создавать новые паттерны без согласования;
- изменять соседние контуры без необходимости.

---

## 5. Правила проверки реализации

После реализации обязательно предоставить:

- список изменённых файлов;
- Diff;
- результаты тестов;
- результаты проверок.

---

## 6. Git правила

Commit выполняется только после приёмки.

Push выполняется только после отдельного разрешения.

---

## 7. Разделение ответственности

Архитектура:
- ADR;
- архитектурные сессии.

Документация:
- ARCHITECTURE.md;
- SESSIONS.md;
- DECISIONS.md.

Процесс разработки:
- PROJECT_RULES.md.

Код:
- текущая реализация проекта.

---

## 8. Приоритет решений

При конфликте использовать порядок:

1. ADR
2. ARCHITECTURE.md
3. PROJECT_RULES.md
4. Existing code patterns
5. Task specification

При конфликте сначала проводится архитектурное решение.
