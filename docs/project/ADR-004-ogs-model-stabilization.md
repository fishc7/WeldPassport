# ADR-004. Стабилизация модели ОГС (welders, admissions, stamp_code)

Дата: 2026-07-06

Статус: принято

Связано: [[docs/project/CONSTITUTION|Конституция]] · ADR «ОГС → Допуски сварщика v0.1».

## Контекст

После реализации `welding.welder_admissions` (v0.1) добавлена таблица
`welding.welders`. Возникло дублирование поля `stamp_code` в двух таблицах и
разные правила создания профиля и допуска. Архитектурный аудит (2026-07-06)
зафиксировал необходимость единого источника истины.

## Решение

### Единые источники истины

| Объект | Владелец | Таблица / поле | Назначение |
|--------|----------|----------------|------------|
| Работник | ОК | `hr.workers` | Кадровая карточка физлица |
| Производственная роль | ОК | `hr.worker_roles` | В т.ч. `WELDER` — право быть сварщиком |
| Профиль сварщика | ОГС | `welding.welders` | Оформление человека как сварщика в контуре ОГС |
| Каноническое клеймо | ОГС | `welding.welders.stamp_code` | **Единственный источник истины** для идентификатора клейма |
| Допуск сварщика | ОГС | `welding.welder_admissions` | Область допуска: методы, материалы, диапазоны, сроки |
| Клеймо в допуске | ОГС | `welding.welder_admissions.stamp_code` | **Денормализованная копия** для поиска и аудита; при создании **обязана совпадать** с `welding.welders.stamp_code` |

### Назначение `welding.welders`

Профиль сварщика — запись о том, что ОГС **оформил** работника как сварщика:
присвоил клеймо, зафиксировал статус (`active` / `inactive` / `suspended`).
Один `worker_id` — не более одного профиля.

Предусловия создания профиля:

1. Работник существует в `hr.workers`.
2. У работника активна роль `WELDER` в `hr.worker_roles`.

### Назначение `welding.welder_admissions`

Допуск — решение ОГС о том, **что именно** сварщик с данным клеймом может варить:
способы сварки, группы материалов, диаметры, толщины, срок действия, основание.

Предусловия создания допуска:

1. Работник существует в `hr.workers`.
2. Активна роль `WELDER`.
3. Существует активный профиль `welding.welders`.
4. `stamp_code` в запросе совпадает с `welding.welders.stamp_code`.

### Цепочка оформления

```text
ОК: hr.workers
  → ОК: hr.worker_roles (WELDER)
    → ОГС: welding.welders (клеймо)
      → ОГС: welding.welder_admissions (допуск)
```

### Именование пакета и API

Пакет backend: `app.welding`. HTTP-префикс: `/api/v1/ogs`. Это осознанное
решение: кодовое имя отражает предметную область, URL — роль владельца (ОГС).

## Отклонённые варианты

1. **Только `welder_admissions` без `welders`** — отклонено: нет явной сущности
   «сварщик оформлен ОГС» до выдачи допуска; клеймо теряет стабильный владелец.
2. **Независимый `stamp_code` в допуске** — отклонено: риск расхождения клейма
   между профилем и допуском.

## Последствия

- Сервисный слой `WeldingService.create_admission` проверяет роль, профиль и
  совпадение клейма.
- В v0.2+ возможны отдельные таблицы `welding.stamps`, `welding.certifications`
  с переносом канонического клейма; до этого `welders.stamp_code` остаётся SSOT.
- Поле `stamp_code` в допуске сохраняется для фильтрации и исторического снимка.
