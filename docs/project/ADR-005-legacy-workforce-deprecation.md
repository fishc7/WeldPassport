# ADR-005. Вывод legacy-модуля workforce из эксплуатации

Дата: 2026-07-06

Статус: принято

Связано: [[docs/project/CONSTITUTION|Конституция]] · ADR-004.

## Контекст

В проекте параллельно существуют:

- **Legacy:** `app.workforce`, API `/api/v1/workers`, `/api/v1/welders`, кириллические
  таблицы в схеме `POSTGRES_SCHEMA` (`РАБОТНИКИ`, `СВАРЩИКИ`, …);
- **Целевой ОК:** `app.hr`, `/api/v1/hr/*`, схема `hr`;
- **Целевой ОГС:** `app.welding`, `/api/v1/ogs/*`, схема `welding`.

`desktop_ok` и часть импортов ещё используют `WorkforceService`.

## Решение

Модуль `workforce` объявлен **deprecated (переходный)**.

**Запрещено:** добавлять новые функции, таблицы и бизнес-правила в `workforce`.

**Разрешено:** исправления ошибок и поддержка существующих потребителей до миграции.

### Целевые контуры

| Область | Модуль | API |
|---------|--------|-----|
| Работники, роли | `app.hr` | `/api/v1/hr` |
| Сварщики, допуски | `app.welding` | `/api/v1/ogs` |

### Стратегия постепенного вывода

1. **Сейчас (стабилизация):** зафиксировать deprecated в коде и документации; все
   новые интеграции — только `hr` + `welding`.
2. **Ближайший этап:** перевести `desktop_ok` на `HrService` / `WeldingService`
   (без расширения legacy API).
3. **После миграции данных:** импортёры пишут в `hr` / `welding`, не в `РАБОТНИКИ`.
4. **Финал:** снять роутер `workforce` с `main.py`, архивировать модуль; legacy-таблицы
   — read-only или удаление по отдельному ADR после бэкапа.

### Миграция данных

Отдельный этап (не в рамках стабилизации 2026-07-06). До него legacy и целевые
контуры **не смешиваются** в одной транзакции без явного ETL-скрипта.

## Последствия

- `app/main.py` сохраняет роутер `workforce` с пометкой deprecated.
- Alembic `WORKFORCE_MANAGED_TABLES` остаётся для legacy-таблиц до их вывода.
- `09_Разработка/src/models/` — отдельный legacy-слой скриптов; не расширять.
