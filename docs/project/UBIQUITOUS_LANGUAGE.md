## Статус термина

Термин считается **утверждённым** только если имеет статус **«Канон»**.

Термины со статусом **«Черновик»** нельзя использовать как основу для БД, API и
бизнес-логики без отдельного архитектурного решения (Architecture Session + ADR).

---

## Назначение

**UBIQUITOUS_LANGUAGE.md** — единый словарь предметной области WeldPassport.

Все архитектурные документы, ADR, код, API, база данных и пользовательская
документация **должны** использовать определения только из этого документа.

Если термин отсутствует в словаре — он считается **неутверждённым** и не может
использоваться как каноническое имя сущности, поля API или таблицы без Architecture
Session и обновления словаря.

Документ обеспечивает одинаковое понимание терминов всеми участниками проекта:

- экспертами предметной области;
- архитекторами;
- разработчиками;
- AI;
- тестировщиками;
- аналитиками.

---

## Правила ведения словаря

Для каждого термина обязательно указывать:

| Поле | Смысл |
|------|--------|
| **Определение** | Что означает термин |
| **Владелец** | Какой домен отвечает за термин |
| **Используется** | Какие домены используют термин (если применимо) |
| **Не является** | Чем данный термин **не** является |
| **Связанные ADR** | Перечень ADR |

Новые термины и изменение определений — только через Architecture Session
([[docs/project/ARCHITECTURE_GOVERNANCE|AGF]]) с обновлением этого файла.

**Статусы записей:**

- **Канон** — определение утверждено;
- **Черновик** — заготовка, ожидает Architecture Session.

# Раздел 2. Производство

## Joint

**Статус:** Канон

### Определение

Инженерная сущность, созданная из утверждённой рабочей документации, являющаяся
**центральным объектом производственного процесса**. Хранится в `engineering.joints`.

Жизненный цикл (`status`, ADR-010/011): `DRAFT`, `PENDING_REVIEW`, `ACTIVE`,
`CANCELLED`, `SUPERSEDED` (последние два — терминальные). Независимые согласования
`pto_status`/`ogs_status` (ADR-011 Р-11-1): `NOT_SUBMITTED`, `PENDING`, `APPROVED`,
`REJECTED`, `REVOKED` — положительное решение называется **`APPROVED`** (не
`CONFIRMED`, который занят `engineering_status` документов). `ACTIVE` — автоматически
при обоих `APPROVED` для текущей `approval_version`.

Три версии (ADR-011 Р-11-2): `record_version` (concurrency), `approval_version`
(значимые данные; к ней привязаны согласования), `workflow_version` (переходы,
блокировки, замена). `ready_for_welding`, `missing_welding_requirements` и
`production_state` **вычисляются** API и в БД не хранятся.

### Владелец

Engineering (`engineering`)

### Используется

Production, Quality, NDT, Executive Documentation (Documents / PTO).

### Не является

- сварочной операцией;
- документом;
- сварщиком;
- вычисляемым производственным состоянием (`production_state`).

### Связанные ADR

ADR-006, ADR-007, ADR-008, ADR-009, ADR-010, ADR-011

---

## WeldOperation

**Статус:** Канон

### Определение

Производственное событие, выполняемое относительно конкретного **Joint**. Хранится
в `production.weld_operations`. Один Joint может иметь несколько операций (этапы
`ROOT`, `FILL`, `COVER`, `FILL_COVER`). Статусы: `DRAFT`, `CONFIRMED`, `VOIDED`;
подтверждённая операция неизменяема. Сварщики: `actual_welder_id` (обязателен) и
`documented_welder_id` (может заполняться позднее).

### Владелец

Production (`production`)

### Используется

Quality, NDT, Executive Documentation (Documents / PTO).

### Не является

- стыком (Joint);
- документом;
- зарплатой или стоимостью работ.

### Связанные ADR

ADR-002, ADR-007, ADR-008, ADR-009

---

## RepairOperation

**Статус:** Канон

### Определение

Производственное событие исправления дефекта сварного соединения относительно Joint.
Связывается с одним или несколькими Defect. Фактическая ремонтная сварка оформляется
как `WeldOperation` с `repair_operation_id`. Defect закрывается повторной Inspection
с `PASS`, а не самим ремонтом.

### Владелец

Production (`production`)

### Используется

Quality, NDT.

### Не является

- повторным NDT без ремонта;
- новым Joint;
- Inspection.

### Связанные ADR

ADR-007, ADR-008, ADR-009

## HeatTreatmentOperation

**Статус:** Канон

### Определение

Производственное событие термической обработки, связанное с Joint. Повторяемое:
каждое событие хранится отдельно с порядковым номером и причиной повтора. Контроль
твёрдости оформляется как Inspection типа `HARDNESS`.

### Владелец

Production (`production`)

### Используется

Quality, Documents.

### Не является

- WeldOperation;
- Inspection;
- протоколом НК (протокол — результат Inspection).

### Связанные ADR

ADR-008, ADR-009

## Inspection

**Статус:** Канон

### Определение

Единая сущность контроля качества стыка: ВИК, НК (RT, UT, PT, MT), контроль твёрдости
(`HARDNESS`), PMI, феррит и др. Тип задаётся полем `inspection_type`. Результаты:
`PASS`, `FAIL`, `CONDITIONAL`. Подтверждённый `FAIL` требует минимум один Defect.

### Владелец

Quality (`quality`)

### Используется

Production, Documents.

### Не является

- WeldOperation;
- Executive Documentation;
- отдельной сущностью на каждый метод НК в MVP.

### Связанные ADR

ADR-006, ADR-008, ADR-009

## Role

**Статус:** Черновик

### Определение

Производственная роль работника в системе (например, `WELDER`), назначаемая ОК.
Права определяются **только действующей ролью**, не должностью (ADR-011 §18).

Технический `role_code` — канон (ADR-010 Р-2); предметные имена ADR-011 —
псевдонимы (ADR-011 Р-11-3):

| Предметное имя (ADR-011) | Технический `role_code` |
| --- | --- |
| `PTO` | `PTO_ENGINEER` |
| `WELDING_ENGINEER` | `OGS_ENGINEER` |
| `PTO_MANAGER` | `PTO_MANAGER` (Task 5B) |
| `CHIEF_WELDER` | `CHIEF_WELDER` (Task 5B) |
| аудитор | `AUDITOR` (Task 5B) |
| системный администратор | системный уровень, не `hr.worker_roles` |

### Область действия роли (scope)

`hr.worker_roles.scope_type` (канон ADR-010 Р-1 / Р-11-4):
`GLOBAL, COMPANY, PROJECT, SITE, LINE, ENGINEERING_DOCUMENT`. Концептуальные уровни
ADR-011 §19 отображаются на канон: `ISOMETRIC → ENGINEERING_DOCUMENT`, `UNIT → SITE`;
литералы `UNIT`/`ISOMETRIC` не вводятся. `COMPANY` — сквозной срез. Проверка — по
иерархии, а не только по совпадению `scope_id`.

### Владелец

HR (`hr.worker_roles`)

### Используется

OGS, Production, Engineering (согласование Joint, ADR-011).

### Не является

- должностью в кадровом учёте;
- допуском ОГС.

### Связанные ADR

ADR-004, ADR-010, ADR-011
