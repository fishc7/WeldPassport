## Статус термина

Термин считается **утверждённым** только если имеет статус **«Канон»**.

Термины со статусом **«Черновик»** нельзя использовать как основу для БД, API и
бизнес-логики без отдельного архитектурного решения (Architecture Session + ADR).

---

## Назначение

**UBIQUITOUS_LANGUAGE.md** — единый словарь предметной области WeldPassport.

Все архитектурные документы, ADR, код, API, база данных и пользовательская
документация **должны** использовать определения только из этого документа.

Если термин отсутствует в словаре — он считается **неутверждённым** и не может
использоваться как каноническое имя сущности, поля API или таблицы без Architecture
Session и обновления словаря.

Документ обеспечивает одинаковое понимание терминов всеми участниками проекта:

- экспертами предметной области;
- архитекторами;
- разработчиками;
- AI;
- тестировщиками;
- аналитиками.

---

## Правила ведения словаря

Для каждого термина обязательно указывать:

| Поле | Смысл |
|------|--------|
| **Определение** | Что означает термин |
| **Владелец** | Какой домен отвечает за термин |
| **Используется** | Какие домены используют термин (если применимо) |
| **Не является** | Чем данный термин **не** является |
| **Связанные ADR** | Перечень ADR |

Новые термины и изменение определений — только через Architecture Session
([[docs/project/ARCHITECTURE_GOVERNANCE|AGF]]) с обновлением этого файла.

**Статусы записей:**

- **Канон** — определение утверждено;
- **Черновик** — заготовка, ожидает Architecture Session.

# Раздел 2. Производство

## Joint

**Статус:** Канон

### Определение

Инженерная сущность, созданная из утверждённой рабочей документации, являющаяся
**центральным объектом производственного процесса**. Хранится в `engineering.joints`.

Жизненный цикл (`status`, ADR-010/011): `DRAFT`, `PENDING_REVIEW`, `ACTIVE`,
`CANCELLED`, `SUPERSEDED` (последние два — терминальные). Независимые согласования
`pto_status`/`ogs_status` (ADR-011 Р-11-1): `NOT_SUBMITTED`, `PENDING`, `APPROVED`,
`REJECTED`, `REVOKED` — положительное решение называется **`APPROVED`** (не
`CONFIRMED`, который занят `engineering_status` документов). `ACTIVE` — автоматически
при обоих `APPROVED` для текущей `approval_version`.

Три версии (ADR-011 Р-11-2): `record_version` (concurrency), `approval_version`
(значимые данные; к ней привязаны согласования), `workflow_version` (переходы,
блокировки, замена). `ready_for_welding`, `missing_welding_requirements` и
`production_state` **вычисляются** API и в БД не хранятся.

### Владелец

Engineering (`engineering`)

### Используется

Production, Quality, NDT, Executive Documentation (Documents / PTO).

### Не является

- сварочной операцией;
- документом;
- сварщиком;
- вычисляемым производственным состоянием (`production_state`).

### Связанные ADR

ADR-006, ADR-007, ADR-008, ADR-009, ADR-010, ADR-011

## WeldOperation

**Статус:** Канон

### Определение

Неизменяемый производственный факт работы **одного фактического сварщика** на
**одном классифицированном этапе** (**один Joint + один сварщик + один этап + один
способ**). Хранится в `production.weld_operations`.

Классифицированные этапы: `root`, `fill`, `cap`, `back_weld`, `tack`. Если разные
сварщики выполняли разные этапы или один этап несколько сварщиков — отдельные
операции на каждого.

Раздельные статусы (не сводить в один):

- `lifecycle_status`: `draft`, `completed`, `superseded`, `cancelled`;
- `welder_confirmation_status`: `pending`, `confirmed`, `not_confirmed`, `not_required`;
- `ogs_review_status`: `not_required`, `pending_review`, `returned_for_clarification`,
  `accepted`, `accepted_with_remark`, `rejected`.

Завершённая операция (`completed`) неизменяема. Производственный факт сохраняется
даже при нарушении допуска, WPS или клейма; нарушение направляется ОГС. WPS на
`Joint` (план) и на операции (факт) разделены. Полная переварка — операция с
признаком `reweld`.

### Владелец

Production (`production`)

### Используется

Quality, OGS, Executive Documentation (Documents / PTO), MTO (будущая связь материалов).

### Не является

- стыком (Joint);
- технологическим решением ОГС (это отдельный review);
- локальным ремонтом (`RepairOperation`);
- корректировкой (`WeldOperationCorrection`);
- документом;
- зарплатой или стоимостью работ.

### Связанные ADR

ADR-002, ADR-006, ADR-007, ADR-008, ADR-009 (частично замещён), ADR-012

---

## WeldOperationCorrection

**Статус:** Канон

### Определение

Отдельная трассируемая сущность исправления завершённой `WeldOperation`. Хранит
исходную операцию, `before_snapshot` / `after_snapshot`, изменённые поля, причину,
согласования и ссылку на заменяющую операцию. Типы: `data_correction`,
`welder_correction`, `technology_correction`, `cancel_false_record`,
`supersede_record`, `import_conflict_resolution`.

Применение атомарно: заменяющая операция становится действующей, исходная —
`superseded`. Параллельные корректировки одной операции запрещены.

### Владелец

Production (`production`)

### Используется

OGS, SMR (согласование СМР), Quality.

### Не является

- прямым редактированием завершённой операции;
- новой первичной сваркой;
- локальным ремонтом;
- решением ОГС (решение ОГС — отдельный контур review).

### Связанные ADR

ADR-012

---

## Reweld

**Статус:** Канон

### Определение

Полная переварка стыка, оформляемая как новая `WeldOperation` с признаком `reweld`.
Обязательны ссылка на исходную отклонённую операцию, классифицированная причина,
решение ОГС, комментарий, автор и дата решения. Черновик `reweld` можно создать до
решения ОГС, но завершить — только после. Локальный ремонт в этот контур не входит.

### Владелец

Production (`production`)

### Используется

OGS, Quality, NDT.

### Не является

- локальным ремонтом (`RepairOperation`);
- корректировкой данных (`WeldOperationCorrection`);
- новым Joint.

### Связанные ADR

ADR-012

## WelderConfirmation

**Статус:** Канон

### Определение

Подтверждение участия фактического сварщика в `WeldOperation`, фиксируемое мастером
или прорабом от имени сварщика. Сварщику не обязателен доступ в систему. Основания:
`personal_confirmation`, `paper_weld_log`, `shift_assignment`, `production_report`,
`other` (с обязательным комментарием). История подтверждений, уточнений и отмен
неизменяема. Отсутствие подтверждения не удаляет производственный факт.

### Владелец

Production (`production`)

### Используется

OGS, Executive Documentation (Documents / PTO).

### Не является

- допуском сварщика (Admission);
- решением ОГС;
- учётной записью сварщика в системе.

### Связанные ADR

ADR-002, ADR-012

## OGSReview

**Статус:** Канон

### Определение

Технологическая проверка и решение ОГС по `WeldOperation` или
`WeldOperationCorrection`: допуск, WPS, клеймо, параметры, несоответствия.
Решения: `accepted`, `accepted_with_remark`, `rejected`, `returned_for_clarification`.
Статус review (`ogs_review_status`) отделён от lifecycle операции и подтверждения
сварщика. При отклонении производственный факт сохраняется; Joint нельзя считать
технологически принятым.

### Владелец

OGS (`welding`)

### Используется

Production, Quality, Documents.

### Не является

- контролем ОТК / НК;
- подтверждением FOREMAN;
- оформлением исполнительной документации ПТО.

### Связанные ADR

ADR-006, ADR-008, ADR-012

## InspectionApplicabilityDecision

**Статус:** Канон

### Определение

Решение о применимости существующего результата контроля после замены или
корректировки `WeldOperation`. Решения: `applicable`, `applicable_with_remark`,
`not_applicable`, `repeat_inspection_required`. Владелец: ВИК — ОТК; RT, UT, PT, MT
и другие методы — НК. При `not_applicable` Joint возвращается в ожидание контроля,
создаётся черновик требования повторного контроля. Полный lifecycle контроля в
Task 8 не входит.

### Владелец

Quality (`quality`) — ОТК для ВИК, НК для методов НК

### Используется

Production, OGS.

### Не является

- новым протоколом контроля;
- Defect;
- автоматической перепривязкой результатов к заменяющей операции.

### Связанные ADR

ADR-006, ADR-012

## Inspection

**Статус:** Канон

> **Уточнение (Session 007, ADR-015).** Определение расширено: `Inspection` —
> **заявка/контрольное мероприятие** с собственным lifecycle, а технический результат
> метода вынесен в `InspectionMethodResult` (см. Раздел 9). Прежняя трактовка ADR-009
> (единая сущность с результатом `PASS`/`FAIL`/`CONDITIONAL`) сохраняется как
> исторический контекст и **частично замещена ADR-015** на уровне метода.

### Определение

Заявка или контрольное мероприятие для одного `Joint` либо утверждённой групповой
выборки (`InspectionSample`). Основной инициатор — **ОГС**. Lifecycle:
`DRAFT → REQUESTED → ASSIGNED → IN_PROGRESS → COMPLETED → REVIEWED → CLOSED`
(+ `SUSPENDED`, `CANCELLED`, `TERMINATED`). Объединяет назначение методов
(`InspectionMethodAssignment`), их выполнение, отчёты, решение ОГС и подтверждённые
`Defect`. Методы: `VT`/`RT`/`UT`/`PT`/`MT` (ВИК — в общем контуре).

### Владелец

Quality (`quality`) / ОГС (инициатор заявки)

### Используется

Production, Documents, Reporting.

### Не является

- `WeldOperation`;
- Executive Documentation;
- техническим результатом метода (это `InspectionMethodResult`);
- технологическим решением ОГС (это `InspectionDecision`).

### Связанные ADR

ADR-006, ADR-008, ADR-009, ADR-015

доступ через короткоживущие подписанные ссылки; замена файла = новая версия.

### Владелец

Лаборатория НК / Documents

### Не является

- официальным отчётом (это `InspectionReport`);
- самим файлом (метаданные + ссылка в хранилище).

## NdtLaboratoryProfile

**Статус:** Канон

### Определение

Профиль лаборатории НК в проекте. Участие лаборатории — через `project_companies` с

методы и внутренний статус лаборатории.

### Владелец

ОГС / Администратор проекта

### Не является

## InspectionState (состояние контроля Joint)

**Статус:** Канон

### Определение

**Вычисляемое** состояние контроля `Joint` (`inspection_state`):
`NOT_REQUIRED`/`PENDING`/`IN_PROGRESS`/`PASSED`/`FAILED`/`REPAIR_REQUIRED`/`REINSPECTION_REQUIRED`.
Основной lifecycle `Joint` **не переписывается** каждым результатом. `PASSED` возможно
только после окончательных принятых результатов по **всем** обязательным методам.

### Владелец

Engineering (вычисляется) / ОГС (принятые результаты)

### Не является

- вручную изменяемым полем;
- `JointProductionState` (отложен, ADR-014);
- основным lifecycle `Joint` (ADR-007).

### Связанные ADR

ADR-015, ADR-014, ADR-012

## Журнал контроля

**Статус:** Канон

### Определение

Отчётное представление контроля из канонических сущностей (а не отдельный ручной
регистр). Форматы: XLSX, PDF, CSV/JSON. Для закрытых периодов создаются неизменяемые
снимки; lifecycle снимка: `DRAFT → GENERATED → VALIDATED → APPROVED → PUBLISHED`
(+ `SUPERSEDED`, `CANCELLED`).

### Владелец

Reporting / Engineering

### Не является

- отдельной первичной бизнес-таблицей ручного журнала;
- механизмом импорта результатов (импорт — интеграционное требование, Session 008).

### Связанные ADR

ADR-015
