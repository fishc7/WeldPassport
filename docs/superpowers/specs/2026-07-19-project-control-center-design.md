# Project Control Center — проектное предложение

Дата: 2026-07-19

Статус: утверждено владельцем проекта

Этап: дизайн; реализация не начата

## 1. Назначение

Project Control Center — отдельная интерактивная система для владельца WeldPassport
и разработчиков. Она показывает фактический ход реализации проекта через жизненный
цикл WeldPassport, объединяя автоматические технические показатели и подтверждённую
владельцем управленческую оценку.

Система отвечает на четыре вопроса:

1. Какой участок WeldPassport уже готов?
2. Что реализуется сейчас?
3. Какие зависимости, риски и решения мешают продвижению?
4. Какой следующий практический шаг имеет наибольший приоритет?

## 2. Принятый подход

Выбран отдельный Project Control Center рядом с основным приложением. Первая версия
работает самостоятельно, но границы frontend и API позволяют позднее встроить
интерфейс в WeldPassport.

Project Control Center не является производственным модулем WeldPassport и не
использует производственные таблицы. Собственные данные хранятся в PostgreSQL в
отдельной схеме `project_control`.

## 3. Пользователи

- Владелец проекта: подтверждает управленческий статус, приоритеты, риски и решения.
- Разработчик: видит задачи, зависимости, Git, GitHub, CI, тесты и причины расчёта
  технической готовности.

Полноценная ролевая модель для всех подразделений WeldPassport в первый MVP не входит.

## 4. Архитектура

```text
Локальный Git ───────┐
GitHub / CI ─────────┤
Тесты и миграции ────┼─> сборщик фактов ─> расчёт готовности ─> API ─> web-панель
Документы проекта ───┘                         │
                                              v
                                  PostgreSQL: project_control
                                              ^
                                              │
                             ручные оценки владельца
```

Компоненты:

1. **Сборщик локальных фактов** читает состояние Git, список миграций, результаты
   проверок и выбранные проектные документы.
2. **Коннектор GitHub** в режиме только чтения получает ветки, коммиты, pull request
   и состояние CI.
3. **Сервис расчёта** формирует прозрачные технические показатели по модулям.
4. **Сервис управления** хранит задачи, зависимости, риски, решения и подтверждения.
5. **Сервис снимков** сохраняет историю прогресса без перезаписи прошлых оценок.
6. **API** отдаёт карту, карточки модулей, историю и данные для разработчика.
7. **Web-панель** предоставляет интерактивную карту и вспомогательные разделы.

Интеграции с Git, GitHub и документами не должны изменять источники.

## 5. Главный экран

Главный экран — интерактивная карта жизненного цикла:

```text
HR → Проекты → Engineering → Подготовка производства → Сварка → Контроль → Закрытие
```

Каждый этап показывает техническую готовность, подтверждённый управленческий статус,
цвет состояния, количество задач, рисков и ожидающих решений, а также зависимости.

При выборе этапа открывается карточка модуля: функции, тесты, миграции,
документация, CI, текущие задачи, блокеры, зависимости и ближайшее действие.

Правая сводная панель показывает состояние ветки, последний успешный сбор данных,
вопросы владельцу, критические риски и следующий практический шаг.

Дополнительные разделы: доска задач, риски и решения, история прогресса, Git и
проверки, настройки расчёта.

## 6. Расчёт готовности

Техническая готовность рассчитывается автоматически:

| Показатель | Вес |
|---|---:|
| Реализованные функции и задачи | 40% |
| Автоматические тесты | 25% |
| Миграции и схема данных | 15% |
| Документация и ADR | 10% |
| GitHub CI и состояние интеграции | 10% |

Вес применяется только при наличии применимого показателя. Неприменимый показатель
исключается, а остальные веса нормализуются до 100%. Отсутствующие или устаревшие
данные не считаются успешными и явно отмечаются в расшифровке.

Владелец не переписывает технический процент. Он присваивает управленческий статус:

- `READY` — готово;
- `READY_WITH_LIMITATIONS` — готово с ограничениями;
- `DECISION_REQUIRED` — требуется решение;
- `BLOCKED` — заблокировано;
- `NOT_CONFIRMED` — оценка не подтверждена.

Итоговое представление всегда показывает оба измерения. Например:
«техническая готовность 86%; управленческий статус — требуется решение».

Общий прогресс проекта рассчитывается как взвешенное среднее модулей. Вес модуля
задаётся явно в настройках и сохраняется в истории; по умолчанию модули имеют
одинаковый вес.

## 7. Основные сущности

- `ProjectModule` — контролируемый модуль или этап жизненного цикла.
- `Milestone` — проверяемая контрольная точка.
- `WorkItem` — задача реализации.
- `Dependency` — направленная зависимость между модулями или задачами.
- `Risk` — риск с вероятностью, влиянием, владельцем и мерами.
- `DecisionRequest` — вопрос, требующий решения владельца.
- `TechnicalMetric` — рассчитанный показатель с источником и расшифровкой.
- `ManagementAssessment` — неизменяемая версия ручной оценки.
- `ProgressSnapshot` — снимок состояния проекта на момент времени.
- `SourceSync` — результат синхронизации с конкретным источником.

У каждой ручной записи есть автор, время, комментарий и история версий. Исправление
создаёт новую версию; прошлые снимки не перезаписываются.

## 8. Потоки данных

### Автоматическая синхронизация

1. Планировщик запускает независимые сборщики источников.
2. Каждый сборщик сохраняет результат и состояние синхронизации.
3. Сервис расчёта обновляет технические метрики.
4. Создаётся новый снимок прогресса.
5. Интерфейс показывает время и качество последней синхронизации.

### Ручное подтверждение

1. Владелец открывает расшифровку модуля.
2. Проверяет технические показатели, риски и открытые решения.
3. Выбирает управленческий статус и вводит обоснование.
4. Система сохраняет новую версию оценки и новый снимок.

## 9. Ошибки и устойчивость

- Недоступность GitHub не обнуляет показатели: используется последний успешный
  снимок с заметным признаком устаревания.
- Ошибка одного источника не останавливает остальные сборщики.
- Автоматическая синхронизация не изменяет ручные оценки.
- Любой процент раскрывается до источников и составляющих расчёта.
- Неполные данные показываются как неполные, а не как нулевая готовность.
- История оценок и снимков не удаляется через обычный пользовательский интерфейс.

## 10. Безопасность

- Интеграция GitHub получает минимальные права только на чтение.
- Секреты не хранятся в репозитории и не выводятся в интерфейсе или журналах.
- Производственная база WeldPassport не подключается к Project Control Center.
- Изменение управленческих оценок требует аутентифицированного пользователя.
- Все ручные изменения журналируются.

## 11. Границы первого MVP

Входят:

1. Интерактивная карта модулей.
2. Карточка модуля.
3. Чтение локального Git и GitHub.
4. Метрики тестов, миграций, документации и CI.
5. Расчёт технической готовности.
6. Ручное подтверждение владельцем.
7. История снимков.
8. Доска задач, риски и ожидающие решения.

Не входят: бюджетирование, календарное планирование, учёт рабочего времени,
управление персоналом, интеграции с мессенджерами и автоматическое редактирование
ADR, roadmap или исходного кода.

## 12. Проверка качества

- модульные тесты расчёта готовности и нормализации весов;
- тесты импорта локального Git и GitHub;
- тесты недоступных, устаревших и неполных источников;
- интеграционные тесты API и PostgreSQL;
- тесты версионирования ручных оценок и снимков;
- frontend-тесты карты, карточки модуля и фильтров;
- визуальная проверка на мониторе и ноутбуке;
- проверка отсутствия операций записи в GitHub и производственную БД.

## 13. Последовательность реализации

1. Модель данных и правила расчёта.
2. Сбор локальных данных.
3. Интеграция GitHub.
4. Backend API.
5. Интерактивная карта.
6. Риски, решения и ручные оценки.
7. История прогресса.
8. Тестирование и подготовка к последующему встраиванию.

## 14. Критерии готовности MVP

- Карта показывает все утверждённые этапы жизненного цикла WeldPassport.
- Для каждого технического процента доступна воспроизводимая расшифровка.
- Владелец может подтвердить статус и увидеть историю подтверждений.
- Недоступный источник не уничтожает ранее собранные данные.
- GitHub и репозиторий используются в режиме только чтения.
- Все автоматические и интеграционные тесты MVP проходят.
- Система развёртывается отдельно от основного приложения WeldPassport.
